# Automated Peer Review & Manuscript Evaluation

PaperOrchestra ships conference-calibrated autoraters under `autoraters/` that you can run on **any** academic PDF—whether generated by PaperOrchestra or written manually by the user!

## 1. Run Conference-Style Ensemble Peer Review (`AgentReview`)

`autoraters/agent_review.py` simulates an ensemble of PhD-level, responsible, constructive reviewers plus an Area Chair meta-reviewer scoring Originality (1–4), Quality (1–4), Clarity (1–4), Significance (1–4), Soundness (1–4), Presentation (1–4), Contribution (1–4), Overall (1–10), Confidence (1–5), and Accept/Reject Decision.

Use [run_review_cli.py](./scripts/run_review_cli.py) `review` to generate both a structured `.json` review and a human-readable `.md` report:

```bash
conda run -n paper_orchestra python skills/paper-peer-review-and-eval/scripts/run_review_cli.py review \
  --pdf paper_output_my_study/final_paper.pdf \
  --ensemble 3 \
  --model gemini-3.1-pro-preview \
  --out-dir paper_output_my_study/external_review
```

## 2. Multimodal Side-by-Side (SxS) Paper Comparison

When comparing two drafts (e.g. `v1.pdf` vs `v2.pdf`, or a generated paper vs. a baseline draft), `autoraters/sxs_paper_quality.py` feeds raw PDFs directly to Gemini (evaluating scientific depth, presentation, figures, and LaTeX formatting side by side):

```bash
conda run -n paper_orchestra python skills/paper-peer-review-and-eval/scripts/run_review_cli.py sxs \
  --pdf-a paper_output_v1/final_paper.pdf \
  --pdf-b paper_output_v2/final_paper.pdf \
  --model gemini-3.1-pro-preview \
  --out paper_output_v2/sxs_comparison.json
```

## 3. Turning Review Feedback into Research Iterations

After generating `review_report.json`:
1. Categorize every item in `"Weaknesses"` and `"Questions"` into one of three buckets:
   - **Presentation / Clarity fix**: Can be resolved immediately in LaTeX or figures (`SectionWritingAgent` / `PlottingAgent`).
   - **Missing Literature / Baseline citation**: Resolve via `literature-and-citations` (`s2_title_search`).
   - **Empirical / Methodological gap (new experiment needed)**: Do **not** paper over missing experiments with speculative prose—route to `end-to-end-research-workflow` to run the missing ablation or baseline, append verified numbers to `experimental_log.md`, and regenerate!
